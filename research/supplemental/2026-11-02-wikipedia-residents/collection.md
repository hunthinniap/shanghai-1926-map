# 2026-11-02 中文维基居民资料全文采集

范围是现有优秀历史建筑名录原名称链接，按解析后的标题去重：408篇中文维基条目，对应421项保护记录，其中420项已上图。没有独立原名称词条链接的名录项不在本轮网页全文范围内，不能把它们记作“词条未提到居民”。

全部408篇均成功取得当前版本的全文wikitext、版本ID与版本时间；无失败、无缺页。单条网页可能涉及机构或建筑群，文章全文的居民记载仍须逐条核对门牌与名录范围。`queue.json`保留词条和名录项的对应关系及原有范围审查。

`raw/`保存22个批量API响应，`manifest.json`保存请求URL、抓取时间、原文SHA-256和文件长度。`pages/`按队列下标保存每篇完整wikitext、便于阅读的派生文字、原网页与固定版本URL；派生文字仅去除部分链接标记与引文模板，不替代原文。中文维基文字依CC BY-SA 4.0使用，条目与版本归属链接随每份页面保留。

`candidates.json`为233篇高召回关键词候选，不是已确认的居住者。关键词包含住宅、故居、曾居、私宅、府邸、下榻、迁入等，因此普通建筑描述、机构迁入和短期酒店下榻也会出现。另175篇未命中该关键词集合，状态记为`no-residence-keywords`；这只是筛查结果，不等于已证明从未有人居住。人物、居住时间、具体楼栋范围均须人工核读后才能进入前端数据。

人工核读中发现便读文本的旧清洗顺序会把自闭合`ref`误当成成对引用起点，导致部分正文不显示；已改为先去除自闭合引用再去除成对引用，重生成全部派生页面和候选并重新核验。原始API响应和完整wikitext始终保留，未受影响。`derived-text-correction.json`列出受影响页面，复核者据此补读；修复后关键词候选由221篇增至233篇。

采集和复核命令（项目根目录，Windows Node 20）：

```powershell
node --preserve-symlinks --preserve-symlinks-main research/supplemental/2026-11-02-wikipedia-residents/collect.mjs
node --preserve-symlinks --preserve-symlinks-main research/supplemental/2026-11-02-wikipedia-residents/collect.mjs --check
```

默认复用已成功保存的批量响应；重跑命令不会自动刷新现有快照。`--check`不联网，逐批核验原文哈希，重新解析全部页面并检查页面文件和清单一致性。请求采用20标题一批、单并发、最小2.2秒间隔，限流时退避，最多3次尝试；本次无重试或失败响应。
