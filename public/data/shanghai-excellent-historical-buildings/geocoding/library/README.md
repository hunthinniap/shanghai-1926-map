# 上海图书馆优秀历史建筑坐标来源

采集入口：[上海图书馆开放数据平台 · 上海市优秀历史建筑](https://data.library.sh.cn/shnh/wkl/webapi/building/toAllBuilding)。此目录为房管局名单补充建筑实体、门址和来源坐标；原始坐标尚未直接作为地图 WGS84 点位使用。

## 文件与重建

- `buildings.json`：1,085 个唯一建筑实体，保留 API 的全部字段，包括 `nameS`、`nameT`、`address`、`long`、`lat`、`uri`。`coordinates` 为数值化后的 **BD-09 原始点位**；API 不提供的批次、精度均保持为空。
- `sources.json`：发布方页面、地图脚本、全集响应及两次分页核对响应的 URL、抓取时间、字节数和 SHA-256。
- `raw/`：五份未经改写的原始响应。
- `validation.json`：原件、分页集合和坐标系证据的核对结果。

在仓库根目录运行：

```sh
node scripts/collect-shanghai-heritage-library.mjs
node scripts/collect-shanghai-heritage-library.mjs --offline
node scripts/collect-shanghai-heritage-library.mjs --check
```

首次命令联网更新；`--offline` 从保存原件重建；`--check` 只读核对 SHA-256 及生成文件是否完全一致。公开目录客户端所用 API key 从发布方脚本读取，未写入来源 URL 参数；作为证据保存的原始脚本保持完整。

## 采集范围与源计数差异

实际接口是 `https://data.library.sh.cn/shnh/gmwx/webapi/architecture/getArchitectures`。采用公开客户端的 `freetext`、`isRed=3`、`pageth`、`iflimit=1` 参数，并将 `pageSize` 设置为 2,000，一次获得完整返回集合。`iflimit=0` 或 `iflimit=false` 在探针请求中均仍分页，不能据此假设已取全。

源 `pager.rowCount` 为 **1,086**，返回 **1,085** 个不同实体 URI。另用 `pageSize=1000` 请求两页，分别返回 **999、86** 条，合并后的 URI 与全集逐项一致。这是发布方响应内部的计数差异，原因未明确；不能虚构第 1,086 条记录。采集器会核对单页与分段集合一致性。

## 坐标系证据

API 只写 `long`、`lat`，并未直接声明 CRS。发布方实际地图客户端 [`allBuilding.js`](https://data.library.sh.cn/res/js/building/allBuilding.js) 提供进一步证据：

1. 保存脚本第 **438—444** 行，在 `mapExcellentHistory` 中将 API 经纬度经 `bd_to_gd` 后才交给 `AMap.Marker`，注释明确为“百度经纬度-转-高德经纬度”。
2. 第 **532—543** 行，`bd_to_gd` 函数注明“百度坐标转高德”，执行减去 `0.0065`、`0.006` 的 BD-09 → GCJ-02 转换公式。

因此这里将源坐标标记为 **BD-09**，证据类型是发布方客户端代码。后续地图应分别记录 BD-09 → GCJ-02 → WGS84 的转换及方法；不能把 RDF 的 `geo:lat/long` 或字段名称本身当作 WGS84 保证。全部 1,085 点在上海宽边界内，但范围核对本身不证明门牌或建筑内部点位准确。
